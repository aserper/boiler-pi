# Dashboard installation

## Reference-styled dashboard

`dashboard-styled.json` follows the owner's selected layout: a large temperature overview beside operating status; aligned pump, consumer-demand and diagnostic panels; and lifetime totals beside a cyan/purple history chart. It uses live values, not the sample numbers in the reference image. The existing Home Assistant sidebar is preserved.

Requirements:

- Home Assistant 2026.10.1+ and Burnham ALTA integration 0.3.0+.
- Frontend resources installed through HACS: **button-card**, **card-mod**, **apexcharts-card**. Refresh the browser after installing new frontend resources.

Installation:

1. Save a backup of the existing dashboard configuration.
2. Open the integration's device page and find the actual entity IDs. In `dashboard-styled.json`, replace each `sensor.ALTA_<KEY>` placeholder with its corresponding entity. IDs are generated by Home Assistant and may include device names or collision suffixes; the integration's internal key is not a guaranteed entity ID.
3. Open a separate dashboard's raw configuration editor and paste the resulting JSON. JSON is also valid YAML and is accepted by the raw editor. Do not overwrite an unrelated dashboard.
4. Confirm actual readings, demand labels, missing-data states and temperature-history rendering on desktop and phone.

The integration's **Configure** screen stores CH1/CH2/DHW display names. The dashboard reads the demand sensors' `consumer_name` attributes, so saved aliases appear without editing the dashboard again. A name you explicitly override in the entity's settings takes precedence, matching Home Assistant's normal behavior. Remove that override if you want the plugin's configured name to apply. Existing entity IDs remain unchanged. Generic defaults do not imply that CH1 and CH2 match individual thermostats; confirm the physical wiring before using floor names.

Pump and demand badges translate only documented 0/1 flags to On/Off. Other values display Unknown. Burner and demand-source text follows the ALTA Extended Features Instructions 112401-01, table 4-4; underlying entities retain raw codes, and unknown codes remain visible. Those labels may need revisiting for different firmware because other manufacturer material contains conflicting enum numbering.

A green diagnostic notice means only that the current hold and lockout codes both report zero—not that the boiler is comprehensively fault-free. Missing diagnostic data is never rendered as a clear condition. Counter word order and temperature-sentinel handling remain provisional.

History uses recorded supply and return readings over six hours. Sparse history is shown honestly; the dashboard does not fabricate a full curve. No automations or boiler controls are included. No extra frontend assets, scripts or remote template URLs are loaded by the dashboard configuration itself.

## Native fallback

`dashboard-ready.yaml` and `dashboard-example.yaml` provide simpler built-in-card alternatives without frontend dependencies. They do not match the custom visual reference as closely.
